# Выход из собственного ярлыка HOME: кандидат 0.17.0

База: `bfe9042cc2166beac3a330b01e1c3b7120e2a104` и текущие незакоммиченные
изменения 0.17.0. Дата проверки: 2026-11-04. Исправление ещё не проверено на Switch.

Пользователь сообщил: после запуска из собственного ярлыка HOME кнопки B на
главной странице и + дают чёрный экран без автоматического возврата. Физическая
кнопка HOME при этом работает. Read-only STATUS при проверке вернул connection
refused; это не определяет, был ли запущен receiver и где остановился выход.

## Подтверждённые проблемы в исходниках

При отсутствии токена receiver не становится resident, `game_reload_main_finish`
возвращает управление, и `main` возвращает 0. Для NRO штатный режим libnx
`__nx_applet_exit_mode=0` возвращает управление загрузчику. Собственный forwarder
не является hbmenu: этот путь не запрашивал системное завершение приложения.

При работающем receiver прежний main разбирал renderer и службы до `finish`,
хотя SDK требует сохранить их до запроса завершения. Сам SDK запрашивает
ISelfController::Exit и затем ждёт без возврата, в том числе при ошибке IPC.
Отдельно штатный libnx перед управляемым выходом Application устанавливает
NoSuspend; прямой вызов SDK этот подготовительный шаг не выполняет.

Источник контракта libnx: [_appletCleanup и _appletExitProcess, v4.12.0](https://github.com/switchbrew/libnx/blob/v4.12.0/nx/source/services/applet.c#L325).
Локально установлен `libnx-4.12.0-1`. Контракт SDK: `third_party/switch-debug-kit/AGENTS.md`,
пункт 4, и `receiver/reload_main.c` / `receiver/reload_launch.c`.

Это доказывает дефекты указанных веток кода, но не локализует точную ветку
аппаратного случая пользователя: токен/resident и место остановки не измерены.

## Изменение

- После `early_bridge`, с проверкой собственного ProgramId и типа Application /
  SystemApplication, устанавливается системный режим выхода libnx. Ранний
  переход bridge → game и запуск из чужого hbmenu сохраняют свой контракт.
- Принятые действия B / + / Exit из собственного HOME вызывают managed exit до
  разборки renderer и workers. Для Application сначала устанавливается NoSuspend.
  Успешный запрос ожидает завершения процесса, не возвращаясь в NRO loader.
- Ошибка подготовки/IPC остаётся на работающем экране с кодом и возможностью
  повторить выход. После отклонённого IPC восстанавливается штатный
  SuspendHomeSleep. Код зависимости не изменён.
- Общий `finish` перенесён перед teardown. Для системного/SDL выхода при resident
  сохраняется существующее ожидание SDK; его поведение при ошибке IPC отдельно
  не изменено и остаётся непокрытым аппаратно.

## Выполненные проверки

В изолированном снимке исходников, PowerShell, Windows, MinGW64:

```powershell
F:\projects\NS\re4-controll-mod\.venv\Scripts\python.exe build.py --test
```

Код завершения 0: 62 Python-теста и полный набор native/SDL-проверок сборщика,
включая новый `app_exit_tests`. Реальный helper исполняется с заменёнными внешними
Switch API: собственный/чужой/нулевой ProgramId, ошибка определения identity,
Application/LibraryApplet/SystemApplication, порядок NoSuspend → Exit,
ошибки focus/Exit, восстановление focus, повтор и отсутствие возврата после
успешного managed exit. Существующие тесты модели покрывают B / + / пункт Exit.

RED до реализации: новый тест не собирался из-за отсутствующего helper.
Дополнительный отрицательный контроль: удаление установки системного режима из
копии helper возвращает прежний tokenless-контракт; тест завершается с кодом 1
на проверке `normal.own_home() && __nx_applet_exit_mode==1`.

Реальный `source/diagnostic/main.cpp` отдельно скомпилирован установленным
devkitA64/libnx с проектными ARM64-флагами и `-Wall -Wextra -Werror`: код 0.
Это проверка компиляции единицы трансляции, не отдельная полная линковка NRO.

## Осталось проверить

Аппаратная проверка именно нового бинарника: запуск из собственного HOME,
B на главной, + из обычных страниц и Gyro test, пункт Exit, повторный запуск;
отдельно запуск без локального токена и с receiver. Проверить сохранность
настроек и работу физической HOME. Запуск через hbmenu и ранний reload bridge
также требуют проверки на консоли. Host stubs не исполняют Horizon IPC,
реальное закрытие процесса или SDL/GPU teardown; исходный симптом не считается
аппаратно исправленным до этой проверки.
