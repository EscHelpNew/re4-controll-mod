# RE4 Controls 0.23.0 — local development build

Раздел **Игра → Внешность персонажа** выбирает Леона, Эшли, Аду, Луиса Серу,
Краузера, Торговца, человеческого Рамона Салазара или деревенского ганадо.
По умолчанию выбран Леон. Выбор сохраняется отдельно от профилей управления;
из оверлея его можно отправить в запущенную игру.

Это визуальная модель поверх управляемого Леона. Его оружие, инвентарь,
действия и сюжетный тип сохраняются. Меню отдельно показывает выбранный и
применённый облик; загрузка остаётся в ожидании, пока новая модель не участвует
в отрисовке. При отказе сохраняется штатная модель. Обычные руки Леона остаются
на оружии; дополнительные кости донора следуют ближайшим основным суставам.

Включено исправление 0.22.1: смена оружия через D-pad сохраняет наклон камеры
и свободный обзор. Все функции 0.22.0 сохранены.

Требуются согласованные модуль и оверлей: wire18/sharedABI22. Старые настройки
переносятся с выбранным Леоном. После обновления приложения полностью закройте
RE4, выберите **RE4 → Установить/обновить мод** и запустите игру заново.

## Engineering scope and validation

The adapter reads authenticated installed resources; public packages contain no
original model or texture assets. Native player type, rig and native mesh chain
remain unchanged. Donor geometry uses mod-owned buffers and bounded retargeting;
hands are appended only through a temporary owned link after suffix validation.

CPU buffer reuse requires a consumed command acknowledgement; full resource
retirement uses post-frame GPU completion. Texture loading, asynchronous file
completion, descriptor admission and allocation ownership have separate gates.
New allocation preserves at least 128 MiB of contiguous native heap capacity.
Unpinned packs follow future native unloads; historical cache is bounded by the
seven donor packs (about196 MiB CPU data worst case), plus model buffers and GPU
textures. This admission reserve does not establish every future engine allocation.

The first adapter applies to supported gameplay Leon, including his normal
weapons. Separate event actors, inventory models and donor-specific facial/cloth
simulation are outside this adapter. Live physical-console visual validation is
still pending.

Final verification: all62 Python checks and every native C++ target passed
(`build/appearance-tests-result.json` records exit0). ARM64 module, overlays and
NRO built successfully; staged native sources match the frozen final source.
Independent final review reported no remaining P1/P2 finding. All986 live native
guard sites match the authenticated game image; no ASLR-sensitive GOT words are
used. Public source/history/release audit passed.
