# RE4 Controls 0.27.2 — current weapon effects and measured tests

Release 0.27.2 (2026-11-08), including all changes since 0.20.0.

- Live cosmetic character selection, natural proportions, height-adjusted cameras,
  owned hands and knives, and right-stick case-model rotation.
- D-pad weapon/grenade cycling, native-font weapon captions with animated mist,
  current attack values in the case, optional additional upgrades and spare ammunition.
- Optional soft grenade explosion marker, pickup-confirmation skipping, startup-logo
  button skipping and aiming-sway removal.
- Normal/Diagnostics launch modes with opt-in automatic diagnostic logs and the
  authenticated read-only overlay diagnostic server.

The details below describe the final fixes and measured validation.

Cosmetic bodies use their own proportions while ordinary weapons retain their
size. Laser, ordinary shot, muzzle-particle and shell consumers now use the same
current grip displacement. The adapter reconstructs the donor displacement from
the native current bone worlds, checks the exact player/held-resource owner and
changes only synchronous math inputs. Native bones, palettes, source descriptors,
directions and spread remain unchanged. Camera-derived ray paths keep their
native handling. Ordinary shot-origin relocation changes the origin used by the
native collision query as well as the displayed ray.

Three narrowly qualified hooks admit 27 authenticated call sites. Persistent
particles retain their native ownership and receive the correction at their
actual consumers, including detached copies. Descriptor changes, stale owners,
retirement and unreadable poses use native fallback. Permission ranges are reused
only inside one callback; live identity, descriptor and pose bytes are read again.
The host fixture measures 11 memory queries per admitted callback, down from 95,
and zero for rejected call sites. This is a query count, not a Switch timing or
frame-rate measurement. Linked ARM inspection confirms original-LR classification,
the native fast paths and pointer ABI.

The spare-ammo count and cosmetic character name now require the actual native
health arc to have been drawn in the same frame. They follow its hierarchy,
fade, screen bounds and disposal rather than surviving on cached sprite records.

Run all tests and coverage with:

```powershell
python build.py --test --jobs 4 --coverage
```

The runner accepts two, three or four workers, isolates each case and translation
unit, retains logs, and rejects failed tests or profile diagnostics. All own C++
and Python sources are accounted for. Unexecuted target-only C++ remains in the
denominator; lines and branches are reported separately. Both languages must
reach 90% executable-line coverage. Input hashes reject source changes during a
run, and production-line exclusions are rejected. Instrumented objects are kept
outside the product build.

The complete module, overlay and NRO build has passed. The trampoline budget is
64 installs in 81 valid slots, with the real allocator boundary checked. The IPC
block remains first in writable data, settings wire 19 and Shared ABI 23 remain
unchanged. The final one-command run passed 104/104 cases: 103 native programs and
175 Python tests. C++ coverage is 10,402/11,419 executable lines (91.09%); Python
is 2,344/2,437 (96.18%). All 137 own C++ files are accounted for, including
target-only code that remains unexecuted. Branch coverage is separate from these
line percentages. The source snapshot stayed unchanged throughout the run.

The NRO embeds the exact newly built module, NPDM and overlay, with module version
0.27.2. Source/history audit found no issues across 762 working files and 1,411
history blobs. Eleven prior frozen NRO hashes were rechecked unchanged; this
release uses a separate versioned directory.
